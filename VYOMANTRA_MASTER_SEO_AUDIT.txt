15. DYNAMIC JOBS & CAREERS ARCHITECTURE AUDIT
================================================================================
Architecture:
  - Hub Page:         careers.html
  - API Endpoint:     api/get-jobs.php (reads MySQL job_postings with data/jobs.json fallback)
  - Subpage Builder:  api/admin/job-builder.php (generates static careers/<slug>.html files)
  - Admin CMS:        api/admin/jobs.php

AUDIT FINDINGS & DEFECTS:
  1. Job Deletion Orphan Defect (P0):
     When an administrator deletes a job or updates its status to "closed" in
     api/admin/jobs.php, the database record and data/jobs.json are updated, BUT the
     compiled static HTML file careers/<slug>.html is NOT deleted from disk.
     It continues to serve a 200 OK static page without any indication of expiration.
     Recommendation: Update api/admin/jobs.php to remove careers/<slug>.html upon deletion,
     or render a clear "This role has been filled" banner with 410 or noindex meta.
  2. UTF-8 BOM in data/jobs.json (P3):
     data/jobs.json starts with a Byte Order Mark (\uFEFF), which causes strict JSON.parse
     in Node.js tools to fail. Remove the BOM character.
  3. Inconsistent Links in Generated Job Pages (P2):
     The job subpage template in api/admin/job-builder.php hardcodes links to
     /privacy-policy and /terms-and-conditions. Update template to /privacy and /terms.
  4. JobPosting Schema Eligibility:
     data/jobs.json is currently empty ([]). Do NOT generate synthetic JobPosting
     schema until live job records with actual salary/terms are published.
